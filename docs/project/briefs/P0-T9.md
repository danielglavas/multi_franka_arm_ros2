# Brief P0-T9: load SlicerIGSIO and SlicerIGT into Slicer

Effort: medium
Type: config. Daniel starts Slicer and checks the modules; Opus prepares the commands. No code,
no subagent, nothing built.

## Goal
Make the "Volume Reconstruction" and "Sequences" modules available in our Slicer, so Phase 4
(recording and reconstruction) can use them. They come from two Slicer extensions that were built
earlier in `~/slicer/modules` but are not loaded when Slicer starts normally.

## What was checked on 2026-11-24 (before writing this brief)
- `~/slicer/modules` holds sources and build folders of **SlicerIGSIO** (git `96ec83b`, 2026-04-17)
  and **SlicerIGT** (git `20ff7ab`, 2023-12-01), built on 2026-04-26.
- Both were built against **this** Slicer: `Slicer_DIR` in their `CMakeCache.txt` (SlicerIGSIO outer
  and inner build, SlicerIGT) is `/home/daniel/slicer/Slicer-SuperBuild-Release/Slicer-build`, the
  build tree we run (Slicer 5.6.2; the Slicer log file name says `Slicer_5.6.2-2024-04-05`).
  Both are `Release`. SlicerIGT points to the SlicerIGSIO build (`SlicerIGSIO_DIR`).
  This settles the "(verify they were built against this Slicer 5.6.2)" note in `PLAN.md`.
- The build outputs exist (`lib/Slicer-5.6/qt-loadable-modules`):
  - SlicerIGSIO: SequenceIO, MetafileImporter, VideoUtil, plus the IGSIO libraries
    (`libvtkIGSIOCommon.so`, `libvtkVolumeReconstruction.so`, …) in `SlicerIGSIO-build/lib/Slicer-5.6`.
  - SlicerIGT: among others **VolumeReconstruction** (`libqSlicerVolumeReconstructionModule.so`).
    So "Volume Reconstruction" comes from SlicerIGT (which uses the IGSIO library), not from SlicerIGSIO.
- **Sequences is part of Slicer itself** since 5.x: `libqSlicerSequencesModule.so` is in the Slicer
  build tree (`Slicer-build/lib/Slicer-5.6/qt-loadable-modules`), source in
  `~/slicer/Slicer/Modules/Loadable/Sequences`. Nothing to load for it.
- Slicer's settings (`~/.config/slicer.org/Slicer.ini`) have no additional module paths
  (`AdditionalPaths=@Invalid()`), so the extensions are not loaded today.
- The SlicerIGT build created a launcher: `~/slicer/modules/SlicerIGT-build/SlicerWithSlicerIGT`
  (ELF executable). Its settings start our normal Slicer
  (`../../Slicer-SuperBuild-Release/Slicer-build/./Slicer`) with
  `--launcher-additional-settings …/SlicerIGT-build/AdditionalLauncherSettings.ini` (library paths of
  both extensions, including the IGSIO libraries and VP9) and `--additional-module-paths` for the
  SlicerIGT and SlicerIGSIO module folders.

Not checked: that Slicer actually loads the modules without errors (only Slicer can show that),
and that SlicerROS2 still loads alongside them (it is installed in the Slicer build tree, so it should).

## Options for loading them
1. **Start Slicer through `SlicerWithSlicerIGT`** (recommended). The launcher is made for exactly
   this, sets the module paths **and** the library paths, and changes no settings file. Cost: a
   different start command; `start_slicer` in `~/start_env.sh` can be changed to use it (separate
   step, only with Daniel's approval).
2. **Add the module folders under Application settings → Modules → Additional module paths.**
   Persistent, normal `./Slicer` keeps working. Risk: this sets only module paths, not library
   paths; the IGSIO libraries (`SlicerIGSIO-build/lib/Slicer-5.6`, VP9) may then not be found and
   the modules fail to load. Would need testing.
3. **Install the extensions into the Slicer build tree** (`make install` / packaging). Most
   permanent, but writes into the Slicer build tree and is harder to undo. Not needed now.

## Steps (option 1)
1. Close Slicer if it runs.
2. Terminal (`source ~/start_env.sh` first, so the ROS2 module still finds ROS):
   ```bash
   ~/slicer/modules/SlicerIGT-build/SlicerWithSlicerIGT
   ```
3. In Slicer's Python console, paste and run:
   ```python
   for name in ["sequences", "volumereconstruction", "sequenceio", "ros2"]:
       print(name, hasattr(slicer.modules, name))
   ```
   Paste the output and any red errors from the Python console to Opus.
4. In the module list (magnifier "Search for modules"), look for "Volume Reconstruction" and "Sequences".
5. Optional: start the sim and add the robot once, to confirm SlicerROS2 still works with this launcher.

## Done when
- `sequences`, `volumereconstruction` and `ros2` print `True`, and both modules open from the module list.
- `STUDENT_GUIDE.md` (section 8) says how to start Slicer with the extensions.

## Alternatives considered
- **A xacro argument choosing DAE or STL**, so RViz keeps its colours. More changes inside
  `franka_description` and in every top-level xacro that passes the argument on. Not worth it for a visual detail.
- **Convert again** with Blender, MeshLab or trimesh. Not needed, since the sources are identical
  and the old STLs were already shown in Slicer.
- **OBJ instead of STL, to keep colours.** Not possible with the installed module: `e7bf7fe`
  reads every mesh with `vtkSTLReader` (`MRML/vtkMRMLROS2RobotNode.cxx:305`) and colours links
  only from URDF `<material>`. (Corrected 2026-11-21; this brief first said both are supported.)
- **Upgrade SlicerROS2 to v1.1+, which loads DAE with colours through Assimp.** Tested upstream only
  on Jazzy and Slicer 5.10/5.12. It is a separate decision with a test build; recorded as D14 in `DECISIONS.md`.

- First try at step 6 failed. `start_panda_sim` stopped with "Unable to parse the value of
  parameter robot_description as yaml".
  - Cause: the explanatory comment added in step 3 contained "DAE: the". xacro copies comments
    inside a macro into the URDF, and ROS launch parses parameters as YAML first, so a colon
    followed by a space makes YAML read the URDF as a mapping.
  - Fix: comment reworded without the colon, plus a note warning about this.
  - Checked: the processed sim URDF (`hand` true and false), the real URDF and the dual sim URDF all load with `yaml.safe_load`.
  - `urdf_tests.py` did not catch this, because it never parses the URDF as YAML.

## Result (2026-11-21)
- **Daniel's check:**
  - The sim starts, the Panda loads in MuJoCo, and SlicerROS2 loads and shows the Panda.
  - Slicer follows the simulation.
- **One difference: in Slicer both fingers always move together.**
  - In the URDF, `finger_joint2` has `<mimic joint="finger_joint1"/>`, so `robot_state_publisher`
    computes the second finger from the first.
  - The sim's `ros2_control` block lists only `panda_joint1` to `panda_joint7`.
  - In `mujoco/franka/panda.xml` the fingers are two joints joined by a **soft** `<equality>`
    constraint (plus a `split` tendon), so a finger pushed in the viewer can move on its own.
  - Slicer and RViz show what tf says, so they keep the fingers symmetric.
  - The real Franka gripper drives both fingers with one motor, so the URDF matches the real
    hardware. The probe replaces the gripper later anyway. No action.
  - Not checked: which node publishes the finger state in the sim, and whether `finger_joint2` appears in `/joint_states`.
